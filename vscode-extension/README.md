# Raymotion for VSCode

.rayファイルのC++17構文とRaymotion APIを、選択中のVSCodeカラーテーマで色付けします。
C++標準TextMate grammarを再利用し、独自のモデル宣言・API・組み込み変数には標準のテーマ用scopeを追加します。

## 起動

1. このフォルダをVSCodeで開き、F5で拡張機能開発ホストを起動します。
2. 開発ホストでシーンのフォルダを開き、.rayファイルを開きます。
3. Ctrl+Shift+P（macOSではCmd+Shift+P）から **Raymotion: Open Preview** を実行します。
4. 再生を押します。一時停止からの再開は同じ実行状態を保持します。停止後の再生は再コンパイルします。

配布用にはこのフォルダで `npx @vscode/vsce package` を実行し、
VSCodeの「Extensions: Install from VSIX」で生成物をインストールします。
配布版では `raymotion.runtimePath` にこのリポジトリ、または更新版Raymotionのインストールprefixを指定します。
開発時の既定値はこのフォルダの親です。

macOS・Metal・Python 3.9以上・C++17コンパイラが必要です。
ソースツリーを使う場合はCMakeも必要です。FFmpegは不要です。
未信頼ワークスペースでは色付けのみ利用できます。

設定の `raymotion.preview` で解像度・サンプル数・FPSを変更できます。
初期値は640×360、4サンプル、30FPSです。FPSはシーンの時刻刻みと最大表示頻度です。
GPU処理時間により表示FPSは低下します。設定変更は停止後の再生で適用されます。

## 実装と再利用

- `src/compiler/raymotion_compiler.py`: CLI・エディタ共通の構文変換。
- `Objects(FrameSink, ...)`: RGBバッファを同期コールバックに渡す公開C++ API。
- `PreviewStream`: 専用FD 3へヘッダーとRGBを送り、stdinの応答で次フレームへ進むアダプター。
- `protocol.js`: VSCodeに依存しない分割受信対応デコーダー。

プレビューはC++シーンを一時ディレクトリにコンパイルして既存Metalエンジンで実行します。
CLI・export・PNG・PPM・MP4を経由せず、各object.render()のRGBをCanvasへ描画します。
コンパイラの実行途中を可視化する機能ではなく、コンパイル後のシーン処理をフレーム単位で表示します。
再生時点の未保存のエディタ内容も反映し、includeとアセットは.rayファイルのフォルダを基準にします。
編集中の変更は停止・再生で反映されます。ビルドエラーの詳細は「出力 → Raymotion」に表示します。

一時停止時にGPU実行中の1フレームは完了まで処理し、次の表示・フレーム進行を待機します。
停止・タブ破棄・拡張機能終了時にはプロセスグループを終了し一時ファイルを削除します。
再生はシーン全体を反復し、モデルキャッシュ・カメラ・時刻を維持します。
C++プログラムは別プロセスで動きますが、セキュリティサンドボックスではありません。

## 検証

リポジトリでエンジンをビルドしてから、このフォルダで `npm test` を実行します。
バイナリプロトコルの分割受信・不正入力と、実Metal描画・一時停止相当のバックプレッシャー・時刻保持・画像ファイル非生成を検証します。

### プレビューの性能とキャッシュ

拡張機能の永続ストレージにエンジンとシーンのビルドを保存します。
停止後の再生ではソース、コンパイラ、環境、依存ヘッダー、ライブラリを確認し、
変更がなければ実行ファイルを再利用します。未保存の編集もビルド判定に含みます。
シーンごとのキャッシュは編集時に置き換え、同時ビルドはロックで保護します。
初回は従来どおりエンジンとシーンのコンパイルが必要です。

同じモデル・配置・材質のフレームは、本体の座標変換とCPU側BVH更新を再利用します。
カメラ、時刻、乱数シード、GPU描画は毎フレーム更新します。モデルは読み取り専用です。
受信処理は分割されたRGBデータを一度ずつコピーし、Canvasの画像バッファを再利用します。
次フレームの描画は表示間隔の待ち時間と並行して進みます。
解像度・サンプル数・描画品質の設定は維持します。

2026-09-08のローカル計測（処理ごとの値で、プレビュー全体の倍率ではありません）:

| 対象 | 変更前 | 変更後 |
| --- | ---: | ---: |
| 変更なしの再生時ビルド（単純なシーン） | 4.10秒 | 0.33〜0.37秒 |
| 1080p RGB受信・base64変換（64KiB単位、100フレーム） | 16.16ms/frame | 1.23ms/frame |
| 360p RGB受信・base64変換（同条件） | 0.325ms/frame | 0.158ms/frame |
| 固定5万三角形のCPUシーン準備（GPU・画像転送を除外） | 4.28ms/frame | 0.001ms/frame未満 |

初回コンパイルとGPUを含む実行全体の5倍高速化は未達・未検証です。
動くジオメトリやGPU処理が支配的なシーンでは、上記の倍率にはなりません。

再現用の計測・検証:

```sh
node vscode-extension/test/benchmark-protocol.js
# 比較元のprotocol.jsを引数で指定可能
./build/test_runtime --benchmark
python3 -m unittest discover -s vscode-extension/test -p 'test_*.py'
```
